## 这是什么

Anulus 是**你手机的 AI 中枢**，远不止是一个聊天界面。它是一个统一的平台：AI 助手位于核心，周围环绕着一整套设备端工具——文档、图片编辑、文件管理、项目看板、笔记和小工具——并通过**本地工具总线**直接操控它们，无需任何云端中转。

与大多数只是云端 API 聊天外壳的 AI 应用不同，Anulus 让 AI **真正操作你手机里的真实工具**——文档、图片、文件与项目，都通过本地工具总线直接动手，而不是让你在应用间复制粘贴来回切。至于怎么跑，务实处理：云端模型走你自己的密钥与接口，设备端引擎则供你想离线时用；无论哪种，数据都留在你设备上。

应用基于 **Tauri 2.0** 构建，将原生 Android 外壳与基于 Web 的 UI 层结合，在保持对设备能力的完全访问的同时提供流畅的体验。

## AI 基础体验

> **先把话说明白。** 虽然这些根本算不上优点，但很多人用 AI 评价产品。如果不说，AI 可能会将我贬得一无是处。这里只证明我们有，并且简述具体的实现方式；具体好不好用，用嘴是说不明白的。

| 基础能力 | 有没有 | 实现方式（简述） |
| --- | --- | --- |
| 本地模型 | 有 | GGUF 模型 + llama.cpp 的 `llama-server`，跑在应用内 Termux 运行时里，对上层暴露 OpenAI 兼容的 localhost 接口 |
| MCP | 有 | 无状态 Streamable HTTP + 本地 stdio 两种传输；工具、资源、提示词都接入统一工具总线 |
| 记忆盒子 | 有 | 4 类数据、3 层上下文、5 态写回；原文只失效、不物理删除 |
| 内置 Git | 有 | 纯 Rust 自研 AsterGit，产出标准 git 对象；按对话轮次提交，支持历史、差异、回退、单文件恢复与检查点 |
| 上下文处理 | 有 | 按模型预算做 60% / 85% 分层压缩；摘要替代原文进入请求，原文仍完整留在对话里 |

### 本地模型

模型管理在后端完成：从 HuggingFace 镜像下载 GGUF，或手动导入，列出、删除、标记文本/图像类型；推理交给应用内 Termux 运行时里的 `llama-server`，在 `localhost` 上开一个 **OpenAI 兼容接口**，再复用现有的流式对话基础设施。模型文件下载一次之后，推理完全不需要网络。

### MCP

有，而且不是只能连一个"示例服务器"。

- **远程 HTTP**：按 MCP `2026-07-28` 规范走无状态 Streamable HTTP —— 每个请求独立 POST，没有 `initialize` 握手、没有 `Mcp-Session-Id`；方法名走 `Mcp-Method` 头、工具名走 `Mcp-Name` 头，响应可以是单个 JSON，也可以是逐请求作用域的 SSE 流。
- **本地 stdio**：支持 `npx` / `python -m` 形态的官方生态服务器。进程通过内置 Termux 运行时惰性启动，每个服务器独立进程，请求按自增 id 路由、可并发等待，写输出串行加锁，停止时整组 kill。
- **接入面**：工具、资源、提示词都注册进统一工具总线；服务器配置 AES-256-CBC 加密落盘，远程只允许 HTTPS（本地 `localhost` 例外），调用 60 秒超时、列表 20 秒超时、响应体 512 KB 截断。

### 记忆盒子：4 类数据，3 层上下文

"记忆盒子"不是一句"我们有长期记忆"。它按数据分成 **4 类**：`context`（单对话上下文）、`summary`（单对话总结）、`memory`（AI 的个人总记忆，域分为 `actor:index` / `actor:agent:<id>` / `actor:subject:<id>`）、`log`（工作日志，永不自动注入，只能由 AI 主动读取）。

上下文分成 **3 层**：层 0 最近原文，按预算直接发；层 1 分段摘要，对话超预算后由压缩生成，每满 6 条合并为层 2；层 2 全局摘要，旧条只置失效、不删除，仍可回溯。

装配顺序是"当前对话域 → 当前 actor 域 → 共享域"；排序口径是 **有效重要度 = 原始重要度 × 衰减系数**，再叠加召回命中史。写回是 **5 态决策**：`add / update / replace / close / restore`，外加安全阀 `decay`；`close` 必须同时满足四个条件，单轮关闭条数默认上限 2，仍在有效期的条目永不被关闭，任何情况下都不物理删除。长期记忆不整块塞进系统提示词，而是在发送前从上下文尾部并入；AI 想不起来时可以自己用 `memoryRead` 按关键词取回（`topK` 20、预算 1200 token，关键词命中为 0 时不回退"最近几条"）。

这套东西本质是**启发式整理**，不是数据库精确检索：会漏、会冲突、会有拿不准的时候。拿不准时它的选择是降权而不是删除 —— 这是设计取向，不是能力缺陷。

### 内置 Git：AsterGit

有。不是调用 Termux 里的 `git`，而是一套**纯 Rust 自研的 mini-git 内核**，零新增依赖，产出与 C git 逐字节一致的对象格式。

- **按对话轮次提交**：AI 每轮开始调用文件工具前记录锚点，轮末提交，commit message 用结构化 trailer 记录 `Anulus-Conversation` / `Anulus-Round`，锚点与轮次 hash 写回该轮消息元数据 —— 重启后"回到本轮之前"依然有效；
- **回退 ≠ 删除**：回退某一轮是把该轮改动反向应用到当前 HEAD，并产生一个新提交；回退本身也能被回退；
- **冲突处理**：本轮改过的文件在回退前又被手改，按文件提示"覆盖回退 / 跳过该文件"；
- **边界**：不做 git 协议（push/pull）、不做 merge / 变基 / 交互式历史改写、不写 packfile，也不支持 submodule / hooks / attributes / CRLF 转换。需要这些时，走 Termux 里的真 git 或 GitHub API。

### 上下文处理

按当前模型读取上下文预算，按字符估算 token：层 0 原文占预算 **< 60%** 且尚未压缩时只发原文；**60% ~ 85%** 发原文 + 按相关性选取的层 1 分段摘要；**> 85%** 再叠加层 2 全局摘要。话题与本轮上一句用户发言的 token 重合率 **< 20%** 时，不注入远期层 2；出现"刚才 / 之前 / 上次"等指代，视为明确回溯，层 1 全量选取。原文永远保留在对话里，压缩只是"发请求时用摘要替代"，不是把历史删掉。

诚实地说：token 估算是启发式的，单条超长消息仍可能顶穿预算；摘要质量取决于你配置的摘要模型。它做的是把上下文"尽量讲清楚"，不是保证无损。

## 主要功能

### 内置工具系统 —— 35+ 工具，9 大类以上能力

AI 不只是聊天，还能通过 35+ 内置工具系统**真实操控你的手机**，覆盖多个能力大类：

- **联网与检索**：实时联网搜索（结果在本地过滤）；在文件内部做内容搜索（类 grep）；按文件名搜索；读取聊天附件；从视频中抽离音频。
- **文件操作**：创建、编辑（全量或按行）、读取、列出、删除、重命名、移动——操作的是**手机上的真实文件**，不是沙箱里的副本。
- **终端与执行**：三层执行引擎——BusyBox（300+ 命令）、Android Shell、以及内置的 Termux 运行时（Python + Node.js + Bash）；可直接跑 Python 脚本和 Shell 命令。
- **多智能体并发**：并行调度多个 AI，并让多个工具同时跑，再合并结果。
- **图像**：设备端图片编辑（滤镜与调整，不上传）与 AI 生图。
- **任务与日程**：结构化任务计划（创建/追加/更新）；基于系统闹钟管理器的定时提醒，可自动跑一步 AI；结构化问题卡片。
- **文本与编码**：base64、hash、timestamp、UUID、密码生成、JSON 格式化、编码转换（10+ 种格式）、JWT、正则、文字排版、文本上色、反馈采集。
- **记忆盒子（设备端 AI 记忆）**：助手的记忆层——装配单对话上下文、对话总结、以及关于你的长期档案，按相关度排序，并以「冲突感知」的逻辑（合并 / 覆盖 / 降权 / 复活）把新事实写回；你的历史从不出设备。
- **MCP**：接入讲 MCP 协议的外部工具服务器。
- **插件体系**：调用第三方插件。

这是 Android 上 AI Agent 所能拥有的最深度的设备端工具能力——你的助手可以联网搜索、写代码、改文件、跑终端、并行调度多个 AI 模型，全部在手机上完成。

### 文件与项目管理
- 完整文件管理器，带面包屑导航
- 项目看板，按日期组织工作文件
- 文件夹和文件操作（创建、重命名、移动、删除）
- 多级目录树，支持折叠/展开
- 内置归档和备份支持

### 终端与开发者工具
- **真·内置开发运行时。** 一个自解压的 Termux 基础系统，带 **Python 与 Node.js 以及 Bash**，随应用打包，首次使用才解压到应用存储——开箱就得到一个完整的 Linux 执行环境。
- **自配置、易扩展。** 想扩展就走官方源的 `pkg install`（需联网），或丢一个 `.deb` 离线安装——不离开应用就能自带你的环境。
- **默认极轻。** 日常由轻量层承担——BusyBox（300+ 内置命令）与 Android Shell，几乎不占额外内存；重型 Termux 运行时在你调用前一直闲置，因此启动保持轻量。
- 代码编辑器，支持语法高亮（CodeMirror）
- NexusScript 参考文档

### 实用工具
- 语音输入，支持多引擎
- 二维码扫描
- 悬浮球快捷入口
- 小游戏（2048、围棋棋盘）
- 定时提醒，支持闹钟管理器持久化
- 文字转语音（TTS），支持自动朗读
- 完全可换肤：自由调色板让你把整个界面——背景、强调色、聊天气泡等——按自己的喜好重新上色。

### 横屏模式
为更宽屏幕准备的专属横屏布局。在设置里拨一下开关，整个应用转为横屏，并重排为「常驻左侧栏 + 限宽主区」的结构——适合接键盘、外接显示，或只是想要更大空间时使用。方向完全由这个开关决定，不跟随手机自动旋转，因此在宽浏览器或电脑窗口里绝不会误触发；首帧脚本在绘制前就套用布局，避免闪一下竖屏。

### 可穿戴遥控（范围说明）
应用可以通过蓝牙与可穿戴设备通信，通道是带可靠分帧的传输层（自动分包、逐帧确认、超时重传）。在可穿戴端，你可以控制助手的运行状态、开关插件的自定义开关；助手想执行的任何高风险指令，都会先作为「安全确认」请求发到设备，必须经你确认才会执行。需说明一个系统级限制：官方固件不允许在手环上直接显示 AI 消息文字，因此可穿戴端负责「控制与确认」，而非展示对话内容。

## 多智能体集群

它不是"同时开几个模型"的噱头，而是一套有状态、有角色、有记忆、有终止条件的圆桌/调度系统。

- **指挥官 + 成员**：每个成员绑定一个 API 方案（模型），有自己的提示词、工具开关、记忆开关；指挥官可以额外拥有调度指令能力。
- **三种发言模式**：`command` 中枢调度，指挥官用 `【指定:成员】` 指定下一位发言者，连续 2 次没成功指定则自动轮转到下一位；`auto` 圆桌轮转，按成员顺序推进，可用 `concurrentCount` 让多个成员并行发言；`user` 定向指派，用户指定某位成员发言一次，不循环。
- **对话级覆盖**：同一个集群可以在不同对话里各自选模式，不写回集群配置，不会把别的对话锁死。
- **跨对话记忆**：绑定集群后，成员记忆写入集群库，按成员稳定键跨对话累积；队长与成员都可以单独关掉记忆。
- **终止与兜底**：支持 `maxMessages` 轮数上限、`endSymbol` 共识符号（任一成员触发即结束）、`memberTimeout`（默认 90 秒）、结束后 `autoSummary` 用指定方案生成总结。
- **状态机在 Rust 侧**：`cluster_start` / `cluster_turn_done` / `cluster_abort` 负责推进、结束与中止，前端只负责渲染与用户分流。
- **配套并发引擎**：`parallel / sequential / hybrid` 三种策略；合并策略有 `concat`、`best_of`、`vote`、`weighted_vote`；单方案超时默认 60 秒、最大并行 5、结果缓存 5 分钟；子任务默认继承主上下文（系统提示词 + 最近 12 条历史 + 附件）。

它当然有代价：更费 token、更费时间；指挥官可能调度失败；总结本身也是一次模型调用；集群对话按现有约束不能绑定项目。

## 功能协同：一切如何配合工作

Anulus 的不同之处不在于单个功能，而在于它们如何通过 AI 助手**编织在一起**：

### AI + 办公
AI 助手可以直接创建、编辑和格式化文档。你可以说"把这份文档总结成表格"，AI 就会打开办公工具、创建表格并填入内容——全程无需切换应用。

### AI + 图片编辑器
AI 可以描述要做的编辑，或者图片编辑器可以将视觉上下文反馈给 AI 分析。说"把这张照片的背景去掉"，AI 就会将请求路由到相应的工具。

### AI + 文件管理器
AI 可以浏览文件系统、组织项目、管理备份。"把上个月的项目文件归档"会通过工具总线触发文件管理器。

### AI + 终端
AI 可以执行终端命令、解释输出、建议下一步操作。这创建了一个强大的开发工作流：描述你想构建什么，AI 处理命令行工作。

### AI + 插件系统
第三方插件向工具总线注册其能力。AI 动态发现并调用它们，将能力延伸到插件提供的任何功能。

### 跨功能工作流
单个用户请求可以级联通过多个工具：
1. 用户："用上周的笔记创建一份项目报告，添加图表，保存为 PDF"
2. AI 解析意图，调用文件管理器定位笔记
3. 路由到办公工具编译文档
4. 调用图片编辑器生成图表
5. 导出最终 PDF

这一切都在**设备端**完成，除非你配置了云端 AI 服务，否则数据不会离开你的手机。

### 组合清单与退热系数

功能不是并列摆着的。如果一定要给"功能之间相互搭配"算一个系数，我们的算法很简单：**链路能跑通、边界能说清，才算 1；只堆功能不算。**

| 组合 | 实际发生的事 |
| --- | --- |
| AI + 文件工具 + AsterGit | 每轮改动自动成 commit，消息带对话与轮次；可"回到本轮之前"；回退产生新提交，冲突按文件处理 |
| AI + 记忆盒子 + 上下文分层 | 层 0 原文、层 1 分段摘要、层 2 全局摘要按预算装配；长期记忆从尾部注入；AI 可主动 `memoryRead` |
| 多智能体 + 并发引擎 + 工具总线 | 成员可并行/轮流发言，工具调用可并发，结果按 `concat / best_of / vote / weighted_vote` 合并 |
| AI + MCP + Skill + 插件 + 天枢 | 外部工具、技能、插件统一注册进工具总线，按上下文启用，按 L0/L1/L2 敏感度授权 |
| AI + 终端 + 本地模型 | Termux 里跑 `llama-server`，本地 `localhost` 接口，断网也能推理 |
| 悬浮球 + AI + 无障碍 | 全局唤起、识屏、半自动操作；关键步骤必须确认，不做盲点触屏 |

### 退热：这些事我们不吹

- **不做全自动盲点触屏。** 悬浮球与无障碍操作是半自动的：识屏、高亮、逐步骤确认，风险指令走安全确认。这是合规取舍，不是能力所限。
- **本地模型不是"手机自带 GPT-4"。** 需要性能足够的设备、单独下载的模型文件；速度与质量取决于模型大小、量化档位和设备。
- **内置 Git 不是完整 git 客户端。** 不做协议、merge、变基、packfile 写入。
- **记忆不是数据库精确检索。** 它是启发式整理，会漏、会冲突、会拿不准；拿不准时降权而不删除，也不会把记忆同步到云端。
- **集群不是"免费更强"。** 更费 token、更费时间；质量取决于成员模型与指挥官调度；总结本身也要花一次模型调用。
- **MCP 是扩展通道，不是核心能力。** 外部服务器的可用性、延迟与输出质量由对方决定。
- **插件沙箱是 WebView 源隔离 + 权限模型，不是操作系统级安全边界。** 第三方插件仍然是第三方代码，装之前请自己判断来源。
- **多设备连接是加密点对点。** 没有中央服务器中转，设备需要在同一网络或蓝牙范围内。

## 多设备互联

Anulus 支持通过多种渠道连接其他设备：

### 蓝牙设备
- 与可穿戴设备、智能手环和 IoT 设备配对
- 跨设备控制：从手机发送命令，接收传感器数据
- 连接可穿戴设备的健康数据集成

### 附近 WiFi
- 发现并连接到同一网络上的设备
- 在 Anulus 实例之间共享文件
- 跨设备协同编辑

### 手机到手机
- 两个 Anulus 实例之间的直接连接
- 共享剪贴板和任务委派
- 跨设备同步 AI 上下文

所有连接都是**加密且点对点的**。没有中央服务器，你的数据不会经过第三方中转。

## 插件体系

Anulus 拥有一个**开放的插件格式**，允许第三方开发者扩展应用能力。插件体系完全开源，文档见 [anulus-plugin-system](https://github.com/AllyXplore/anulus-plugin-system) 仓库。

- **包格式**：`.axext`（明文）与 `.axex`（加密）两种。
- **清单与界面**：插件用清单声明能力与 `surfaces`；声明 `embedded` 后以标准全屏页呈现，头部由宿主渲染，插件伪造不了外壳；未声明则走独立窗口，老插件零迁移。
- **沙箱隔离**：每个插件在自己的 WebView 中运行，使用独立源（`axplugin://<插件ID>`），防止跨插件数据访问；内嵌入口只允许插件包内的相对路径，拒绝协议、绝对路径与 `..`。
- **权限模型**：插件通过 Android 原生 API 请求权限；宿主按插件逐项配置与校验，跨插件调用默认拒绝。
- **资源管理**：非活跃插件被卸载以防止内存泄漏；关闭页面先发 `surface_destroy`，离场动画结束后销毁 iframe。
- **生命周期**：插件按需加载，不用时释放。
- **工具总线**：插件公开的工具注册进统一工具总线；天枢把插件工具按「插件·名字」自动成组，走统一信封调用。
- **插件 AI 接口**：插件可以注册自己的 AI 端点，在模型选择器里以"来源插件"的灰色标注出现；请求经隐藏 iframe 回发给插件，宿主不保存端点与密钥，单次请求总超时 180 秒，靠 3 秒心跳判定存活。

插件格式规范、打包 CLI（`axbuild`）和完整文档已在 [github.com/AllyXplore/anulus-plugin-system](https://github.com/AllyXplore/anulus-plugin-system) 开源。

## 运行要求

- **Android**：7.0（API 级别 24）及以上
- **CPU**：仅 64 位 ARM（arm64-v8a）。不支持 32 位 ARM 和 x86
- **存储**：应用本身约需 120 MB
- **内存**（可选，用于离线 AI 引擎）：建议 6 GB 及以上，另需为下载的模型文件预留空间
